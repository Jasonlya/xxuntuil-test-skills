## 1 功能点

功能点是需求的最小可分配单位，也是证据与分析项的挂载点。粒度标准：一个功能点对应一段「用户能描述出来」的行为。

| 编号 | 功能点 | 用户可感知的行为 | 优先级 | 来源 |
|---|---|---|---|---|
| FP-01 | 账密登录 | 输入账号密码，校验通过后进入首页并保持登录 | P0 | [SRC-REQ] PRD §2.1 |
| FP-02 | 短信验证码登录 | 输入手机号获取 6 位验证码，验证通过后进入首页 | P0 | [SRC-REQ] PRD §2.2 |
| FP-03 | 失败锁定与解锁 | 连续输错达到阈值后账号锁定，锁定期内无法登录，到期自动恢复 | P0 | [SRC-REQ] PRD §3.1 |
| FP-04 | Token 下发 | 登录成功返回 access token 与 refresh token | P0 | [SRC-API] POST /api/auth/login |
| FP-05 | 第三方 Token 校验 | 第三方持 token 调用校验接口，得到有效 / 无效结论 | P1 | [SRC-DOC] 接入文档 §4 |

**本期不做**

- 不接第三方 OAuth / 企业微信扫码登录
- 不做多因子认证（MFA）
- 不做单点登录（SSO）

## 3 证据

一条证据 = 一个能落到具体位置的原句或代码片段。**转述不算证据**，写「详见 PRD」也不算——第三人要能拿着这一行独立核对。

| 编号 | 支撑对象 | 来源类型 | 位置 | 原文摘录 | 强度 |
|---|---|---|---|---|---|
| EVD-01 | FP-01、TA-01、TA-02 | SRC-API | auth.yaml#/paths/~1api~1auth~1login | `200 → {access_token, refresh_token}` / `401 → {code: AUTH_FAILED, message: 账号或密码错误}` | 强 |
| EVD-02 | FP-03、TA-08、TA-09 | SRC-REQ | PRD §3.1 | 「连续输错 5 次锁定 30 分钟，到期自动解锁」 | 强 |
| EVD-03 | FP-03、TA-10 | SRC-CODE | auth/lock.go:88-104 | `if user.FailCount >= 5 { user.LockUntil = now.Add(30 * time.Minute) }` | 强 |
| EVD-04 | FP-05、TA-12、TA-13 | SRC-DOC | 接入文档 §4 | 「校验接口对无效 token 返回 200 与 valid=false，避免调用方按 HTTP 状态分支」 | 中 |
| EVD-05 | FP-02、TA-06 | SRC-REQ | PRD §2.2.4 | 「同一验证码只能成功校验一次，重复校验返回 CODE_USED」 | 中 |
| EVD-06 | OQ-01 | SRC-VERBAL | 11-25 需求评审录音 12:30 | 「锁定先按账号做，IP 那块后面再说」 → OQ-01 | 弱 |
| EVD-07 | FP-04、TA-11 | SRC-API | auth.yaml#/components/schemas/TokenPair | `access_token: {expires_in: 7200}` / `refresh_token: {expires_in: 604800}` | 强 |

**证据缺口**

- FP-02 的验证码有效期（300s）与重发间隔（60s）只有 PRD 一处来源，代码与接口定义都没有体现 → 需后端确认实现是否与文档一致（缺口）
- TA-13 的性能阈值只有接入文档一句话，压测基线缺失 → 交付前要么补基线，要么降级为待澄清（缺口）
- FP-04 的 refresh 轮换策略无任何来源 → 已在 OQ-03 提出（缺口）
