# 需求模型：优惠券下单抵扣

> **基线**：`main@7f3a9c2`（2026-11-25 拉取）
> **分析人 / 日期**：测试开发 · 2026-11-26
> **来源清单**：PRD v1.3（`需求-优惠券下单.md`）、接口定义 `openapi.yaml`、技术设计 `架构 §5`、代码 `coupon-service`、缺陷单 `BUG-2211`
> **可信度说明**：本模型每条结论均带来源；口头来源已全部转为待确认事项（见第 11 段）

## 1. 目标与非目标

**目标**：用户下单时可使用一张优惠券抵扣订单金额，抵扣后实付金额正确，券状态按预期流转。

**成功标准**：
- 原价 = 抵扣金额 + 实付金额，恒等成立
- 同一张券在任意并发下只被一个订单成功抵扣

**非目标（本版明确不做）**：
- 不支持多张券叠加使用
- 不支持跨店铺券
- 不支持券转赠或退回账户外
- 不改造 promotion-service 的面额计算引擎，本需求只验消费侧

## 4. 数据契约

| 编号 | 字段 | 类型 | 必填 | 边界 | 来源 | 校验时机 |
|---|---|---|---|---|---|---|
| FLD-01 | couponId | string(32) | 是 | 必须属于当前登录用户 | [SRC-API POST /orders] | 下单前置校验 |
| FLD-02 | discountAmount | int64（分） | 是 | ≥0，≤券面额，≤订单金额 | [SRC-API POST /orders] | 下单计算 |
| FLD-03 | orderAmount | int64（分） | 是 | ≥1 | [SRC-API POST /orders] | 下单 |
| FLD-04 | payAmount | int64（分） | 是 | = orderAmount − discountAmount，且 ≥0 | [SRC-API POST /orders] | 下单 |
| FLD-05 | expireAt | timestamp | 是 | 晚于 createdAt，最长 365 天 | [SRC-CODE Coupon.java:45] | 领取时写入 |

**缺失值语义**：不传 couponId 时不走抵扣逻辑，`discountAmount=0`；传了非法 couponId 直接拒绝，不做静默降级 → [SRC-API 参数说明]

## 6. 业务规则

| 编号 | 规则（可判真假的陈述） | 来源 |

| REQ-02 | 抵扣金额不得超过券面额，也不得超过订单金额 | [SRC-REQ §3.2] |
