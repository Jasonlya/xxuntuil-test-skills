# 需求歧义的八类模式

阶段二按此表**逐类过筛**，不是想起来才查。每类给了识别信号、为什么危险、以及可直接复制的问法。

过筛方式：拿第 6 段的每条 `REQ-*` 和原文对应段落，依次套八类。命中即记一条 `OQ-*`，写完八类再统一提问。

---

## 1｜量词与范围缺失

**识别信号**：支持多端 / 兼容主流浏览器 / 大量数据 / 高频操作 / 若干 / 等等 / 其他场景。

**为什么危险**：范围直接决定测试矩阵大小。「多端」是 2 端还是 7 端，工作量差一个量级；「主流浏览器」在需求方心里的清单和团队实际支持清单经常不同。

**怎么问**：

> 「支持多端」具体包含哪些端？请给清单（如 iOS / Android / H5 / 小程序 / 桌面端）。**不在清单里的端，本版是否明确不支持？**

> 「兼容主流浏览器」请给到具体版本号下界；无法给出时，是否接受「以当前桌面端最新两个大版本为准」这一默认？

**判未决的标准**：给不出清单，且无法裁定「本版不做」→ 未决项。

---

## 2｜时间边界模糊（必须双侧）

**识别信号**：及时 / 尽快 / 实时 / 当天 / 月底 / 过期后 / 一段时间内 / 超过 N 天。

**为什么危险**：只问单侧的边界是测试里最常见的漏测来源。写「30 分钟未支付自动关闭」，只测 31 分钟是不够的——**29:59 必须仍可支付**。边界值的另一侧才是「没有提前误杀」的证据。

**怎么问**：

> 「及时通知」的时限是多少？以什么事件为计时起点、什么为终点？

> 「30 分钟未支付关闭」——29 分 59 秒时是否仍可支付？关闭动作由什么触发（定时任务 / 惰性判断）？触发频率多少（决定实际关闭时间可能晚多久）？

**注意**：自然日、工作日、时区、夏令时都要问。「当天」在 23:59:59 下单、00:00:01 支付算不算当天，是一个真实的资损边界。

---

## 3｜角色重叠与自审自批

**识别信号**：管理员 / 运营 / 有权限的用户 / 审核人 / 审批流 / 可代为操作。

**为什么危险**：需求文档通常只写「谁能做什么」，不写「同一个人能否既提交又审批」。这个空白在实现里往往被默认放行，形成越权或内控缺陷。

**怎么问**：

> 一个用户同时具备「提交」和「审批」权限时，能否审批自己提交的单据？若允许，是否需要二次确认或留下审计记录？

> 「管理员」与「超级管理员」的权限差集是什么？请给差集，不要给并集。

> 角色被撤销的瞬间，已打开页面上的操作按钮是否立即失效？还是刷新后才失效？

---

## 4｜状态与终态遗漏

**识别信号**：状态图只有主链路 / 只有正向箭头 / 没有终态 / 没有「已取消」「已关闭」「已失效」。

**为什么危险**：主流程通常写得清楚，**异常态和终态基本不写**。而线上问题绝大多数发生在异常态：订单取消后优惠券是否退回、退款后积分是否扣回、任务失败后能否重试。

**怎么问**：

> 除主链路外，每个状态是否还有「取消 / 超时 / 失败 / 驳回」的出口？请给完整状态清单。

> 哪些状态是终态（不可再流转）？进入终态的逆操作（撤销 / 重开）是否支持？

> 状态 A 直接跳到状态 C（绕过 B）是否允许？如果不允许，系统怎么拦截——报错、静默忽略、还是数据不一致？

**闸门要求**：第 3 段每个状态至少一条非法迁移，且要写明**拦截方式**。

---

## 5｜数据来源与缺失值语义

**识别信号**：自动填充 / 默认值 / 从上游获取 / 取最近一次 / 为空时。

**为什么危险**：字段「从哪来」和「没有时填什么」是两个独立问题，需求文档通常只写前者。缺失值语义不明确，就会出现同一字段在不同页面显示不同结果。

**怎么问**：

> 字段 X 从哪个系统的哪个接口取？取不到时（超时 / 返回空 / 返回 null）显示什么——空、`-`、`0`、还是沿用上一次的值？

> 「取最近一次」的排序依据是什么字段？同一时间戳有多条时取哪条？

> 该字段可编辑吗？可编辑时，上游后续更新会不会覆盖人工修改的值？

---

## 6｜失败语义与回滚

**识别信号**：调用失败 / 异常时提示 / 重试 / 部分成功 / 补偿。

**为什么危险**：失败后的**数据状态**几乎从不写在需求里。「失败给个提示」这种描述下，数据库里可能留下半条脏数据，而没人知道该不该清。

**怎么问**：

> 该操作涉及多个子步骤时，某一步失败，已成功的步骤是否回滚？整体是原子操作还是允许部分成功？

> 失败后是否允许用户立即重试？重试会不会产生重复数据（幂等键是什么）？

> 失败时用户看到什么？系统内部留下哪些痕迹（日志 / 中间状态 / 待补偿任务）？由谁在什么时候清理？

---

## 7｜权限与可见性混谈

**识别信号**：看不到 / 隐藏 / 脱敏 / 无权访问 / 仅自己可见。

**为什么危险**：「看不到」有三种完全不同的实现，测试方法和风险等级差很远：

| 表述 | 实现 | 风险 |
|---|---|---|
| 前端隐藏 | 接口仍返回数据 | 抓包即可绕过，属越权 |
| 接口不返回 | 数据不出服务端 | 正常 |
| 脱敏返回 | 返回但掩码 | 掩码规则本身要测 |

**怎么问**：

> 「无权用户看不到该数据」——是指接口不返回、返回但掩码、还是仅前端不展示？请明确到接口层。

> 掩码规则是什么？按角色还是按数据归属？掩码后能否通过导出 / 打印 / 复制绕过？

---

## 8｜口径不一致

**识别信号**：同一指标在两处出现不同叫法（金额 / 应付金额 / 实付金额；用户数 / 活跃用户 / 去重用户），或同一词在不同文档里定义不同。

**为什么危险**：口径不一致不会导致功能报错，只会导致**对账差异**，而且往往上线后才发现。测试开发在这里的价值是提前把两个定义摆在一起。

**怎么问**：

> 「日活」是自然日去重还是滚动 24 小时？统计时区是 UTC 还是本地？跨零点登录算一天还是两天？

> 金额字段的口径：单位是元还是分？含不含税？含不含运费？退款后是否计入 GMV？

> PRD 第 3 章写「应付金额」、接口文档写 `pay_amount`、代码里叫 `actualAmount`——这三者是同一个值吗？请确认映射关系并给一个算例。

---

## 使用建议

1. **先扫 2、4、6 三类**——它们对应时间边界、状态异常、失败回滚，是线上问题最集中的区域。
2. 每条命中写成 `OQ-*`，第 11 段必须填「向谁确认」，不能只写问题。
3. 一次问完再找需求方，不要一条一条打断。按影响面排序，把影响规则条数最多的放最前面。
4. 需求方回答「你们看着办」时，把这句话连同日期记进裁决列，并写明你选取的保守分支——**这也是裁决**，不是没有裁决。
