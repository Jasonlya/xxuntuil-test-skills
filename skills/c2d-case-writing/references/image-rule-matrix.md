# 图片校验场景矩阵（image-rule-matrix）

> C2D 图片校验的**场景全集**。写用例时从本表取场景，按「本项目裁剪」划掉不测的并写理由。
> 表内「必配图片特征」是本 skill 的核心：**每个场景都规定了能触发它的图片长什么样**。
> 图片不对，用例等于没写——这是图片类用例与普通功能用例最大的差别。

## 用法

1. 逐行过表，对本项目判断 include / exclude（exclude 必须写理由：无此能力 / 本期不涉及 / 风险已由研发侧兜底）
2. include 的场景 → 从 `image-fixture-registry.md` 取对应槽位（FIX-xx），或按「必配图片特征」自备
3. 一个场景 ≥1 条用例；边界密集的场景（尺寸、倍率）用边界值法展开
4. 表内规则编号 `IMG-*` 直接写进用例的「规则」字段，便于回归时按规则反查用例

## 场景组 A｜设计稿侧填充（MasterGo imageFill）

| ID | 场景与触发条件 | 必配图片特征 | 可判定预期 |
|---|---|---|---|
| IMG-FILL-01 | 单图片填充，`fills` 只有 1 个 `type === "IMAGE"` 的 Paint | 任一正常位图，比例与容器接近（1:1 或 4:3） | 导出的图片像素内容与设计稿一致；`imageRef` 唯一；代码侧 `img` 的 `src` 指向该图 |
| IMG-FILL-02 | 多图片填充叠加：`fills.length ≥ 2` 且有 ≥2 个 IMAGE | 两张**颜色差异极大**的图（如一张纯黑 FIX-SOLID-BLACK + 一张正常照片），后叠的须能明显覆盖前层 | 导出结果 = 按 fills 顺序合成后的样子；不得只导出最后一层；代码侧不得只剩一张 |
| IMG-FILL-03 | 填充模式 FILL（覆盖裁剪） | 长宽比与容器**明显不同**的图（3:1 图放进 1:1 容器，或反向） | 铺满容器无留白；按 cover 语义裁切；无拉伸变形 |
| IMG-FILL-04 | 填充模式 FIT（完整显示） | 长宽比与容器明显不同的图 | 图片完整可见、比例不变，容器留空区域按设计稿底色/透明填充 |
| IMG-FILL-05 | 填充模式 STRETCH（拉伸） | 3:1 或 1:3 的极端比例图 | 图片被拉伸到容器尺寸，比例失真（这是预期，不是缺陷）；断言「失真确实发生」 |
| IMG-FILL-06 | 填充模式 TILE（平铺） | **极小图**（≤32×32，如 FIX-1X1 / 小图标） | 平铺重复出现，间隔与设计稿一致；不得被缩放成单张铺满 |
| IMG-FILL-07 | 同一 `imageRef` 被多个节点复用 | 一张图，配 3 个不同尺寸容器引用 | 导出去重（不重复上传同一图）；各节点按自身尺寸/模式渲染正确 |
| IMG-FILL-08 | 图片填充 + 图层透明度 <1 | 高对比图（黑白格或纯色块） | 透明度生效，且代码侧用 `opacity` 而非改图片像素 |
| IMG-FILL-09 | 图片填充 + 混合模式（multiply / screen 等） | 浅色底图 + 深色前景图 | 混合结果与设计稿视觉一致；代码侧保留 `mix-blend-mode`（降级时须记录） |
| IMG-FILL-10 | 图片填充 + 渐变叠加（IMAGE + GRADIENT 两层） | 纯色或低对比图（便于观察渐变） | 渐变层叠在图片上；导出不得把渐变烘焙进图片（应能分离） |

## 场景组 B｜裁剪、蒙版与几何变换

| ID | 场景与触发条件 | 必配图片特征 | 可判定预期 |
|---|---|---|---|
| IMG-CROP-01 | 圆角容器裁剪图片（radius > 0） | 四角有明显内容的图（如文字/边框），不可用纯色 | 四角按圆角裁掉；代码侧用 `border-radius` + `overflow:hidden` 或等价；半径与设计稿一致（±1px） |
| IMG-CROP-02 | 圆形/椭圆裁剪（radius = 50%） | 人脸或居中对称为佳（便于观察是否偏心） | 圆形完整；不得出现椭圆或被压扁；主体居中 |
| IMG-CROP-03 | 蒙版（mask）裁剪：图片在 mask 图层内 | 大面积纯色/渐变图（便于看清蒙版边界） | 只保留蒙版形状内区域；蒙版外透明；代码侧用 `clip-path` 或 mask |
| IMG-CROP-04 | 图片图层旋转（非 0/90/180/270 度） | 直角/网格类图（可观察角度是否失真） | 旋转角度一致；裁剪边界不吞掉旋转后外扩的角 |
| IMG-CROP-05 | 图片图层水平/垂直翻转 | **含可辨方向的图**（文字、箭头、人物朝向） | 翻转生效；不得用负 margin 等 hack 伪装 |
| IMG-CROP-06 | 描边（stroke）叠加在图片图层上 | 深色图 + 浅色描边 | 描边可见且不被图片覆盖；inner stroke 不得被裁掉 |
| IMG-CROP-07 | 图片超出父容器（overflow） | 大于容器的图 | 按设计稿 overflow 语义（hidden / visible）处理；hidden 时不得溢出滚动条 |
| IMG-CROP-08 | 自定义裁剪（crop 矩形非全图） | 带明显分区的大图（如四象限不同色块） | 只导出裁剪区域；裁剪偏移正确（用分区色块判断切错了哪一块） |

## 场景组 C｜导出与格式

| ID | 场景与触发条件 | 必配图片特征 | 可判定预期 |
|---|---|---|---|
| IMG-EXP-01 | 导出 PNG | 需要透明的图（FIX-ALPHA） | `Content-Type: image/png`；透明通道保留；边缘无白边 |
| IMG-EXP-02 | 导出 JPG | 照片类 | `image/jpeg`；透明区域按声明底色填充（不得是黑块） |
| IMG-EXP-03 | 导出 WEBP | 照片类 | `image/webp`；浏览器实测可渲染 |
| IMG-EXP-04 | 导出 SVG（矢量节点） | VECTOR 类型图标，非位图 | `image/svg+xml`；矢量可缩放不糊；不得把位图包进 SVG（体积异常增大） |
| IMG-EXP-05 | 倍率 scale = 2（或 3） | 任意位图 | 导出像素 = 设计尺寸 × scale；文件名/代码引用带倍率标识 |
| IMG-EXP-06 | 裁剪到图层边界 | 内容贴边的图 | 导出无多余透明边；若保留透明边须在用例中显式声明为预期 |
| IMG-EXP-07 | 超大图（≥4096 边长，如 FIX-HUGE） | 4096×4096 实测 2.6MB | 按策略处理：压缩 / 分片 / 拒绝并报错，行为须与产品约定一致；有明确体积阈值 |
| IMG-EXP-08 | 极小图（1×1，FIX-1X1） | 1×1 jpeg | 不崩溃；不得被静默丢弃；渲染为纯色块或按 TILE 平铺 |
| IMG-EXP-09 | 极端比例（300:1，FIX-ULTRAWIDE） | 3000×10 | 不崩溃；渲染不产生明显拉伸伪影；有比例上限则明确报错 |
| IMG-EXP-10 | 导出失败降级 | 故意 404 或非图片资源（FIX-BROKEN-404） | 失败可见（报错/占位），不得静默生成空图或 0 字节文件 |

## 场景组 D｜生成代码的图片渲染

| ID | 场景与触发条件 | 必配图片特征 | 可判定预期 |
|---|---|---|---|
| IMG-CODE-01 | 生成 `<img>` 且 `src` 为可访问直链 | 正常位图 | HTTP 200 + `image/*`；`src` 不是 base64 内联（除非体积 < 阈值且用例声明） |
| IMG-CODE-02 | `src` 必须不是占位符 | — | 代码中无 `placeholder` / `example.com` / `xxx.png` / `src=""` |
| IMG-CODE-03 | 宽高比保持 | 非正方形图 | `width/height` 属性或 `aspect-ratio` 与设计稿一致，避免布局抖动（CLS） |
| IMG-CODE-04 | `object-fit` 与设计稿填充模式对应 | 与容器比例不同的图 | FILL→cover、FIT→contain、STRETCH→fill，逐档核对 |
| IMG-CODE-05 | `object-position` 决定裁剪焦点 | 主体偏一侧的图 | 焦点与设计稿一致（用主体位置判断，不靠肉眼"感觉对"） |
| IMG-CODE-06 | 背景图 vs `<img>` 选择 | 装饰性 vs 内容性图片 | 内容图用 `<img>`（可 alt、可 SEO）；纯装饰可用背景图。误用须记为问题 |
| IMG-CODE-07 | `alt` 文本 | — | 内容图有语义化 alt；纯装饰图 `alt=""`；不得是文件名 |
| IMG-CODE-08 | 懒加载 | 长页面多图 | `loading="lazy"` 生效；首屏图不得懒加载（会拖慢 LCP） |
| IMG-CODE-09 | 多倍率 `srcset` | 同一图 1x/2x | `srcset` 正确，浏览器按 DPR 选择；不得全部指同一文件 |
| IMG-CODE-10 | 路径编码 | 含空格/中文/大写的文件名 | URL 编码正确；大小写敏感环境下不 404；中文名已转义或改名 |
| IMG-CODE-11 | 响应式断点下裁剪 | 3:1 横幅，测 390px 与 1200px 两档 | 窄屏裁切后主体与标题仍完整（不得把主体裁掉） |

## 场景组 E｜加载失败与降级

| ID | 场景与触发条件 | 必配图片特征 | 可判定预期 |
|---|---|---|---|
| IMG-FALL-01 | 图片 404 | FIX-BROKEN-404（实测 404 text/plain） | 显示占位/底色/alt 文本；不得出现破图图标或大片空白 |
| IMG-FALL-02 | 非图片资源（返回 HTML） | FIX-BROKEN-HTML（实测 404 text/html） | 同上；不得把 HTML 当图渲染 |
| IMG-FALL-03 | 跨域 / 防盗链拒绝 | 需内网或第三方限制外链的图（TODO） | 失败可观测且降级正确；不得静默空白 |
| IMG-FALL-04 | 弱网 / 慢加载 | 大图 FIX-HUGE | 有骨架屏或占位；布局不因加载完成而大幅跳动 |
| IMG-FALL-05 | 图片加载中不阻塞交互 | 任意 | 加载期间页面可操作；不得整页白屏等待 |

## 场景组 F｜视觉一致性

| ID | 场景与触发条件 | 必配图片特征 | 可判定预期 |
|---|---|---|---|
| IMG-VIS-01 | 设计稿 vs 渲染截图比对 | 高对比、边界清晰、无渐变的图（便于 diff） | 差异像素比 ≤ 阈值（阈值须写进用例并注明来源）；差异区域定位可复现 |
| IMG-VIS-02 | 色差 | 纯色块（FIX-SOLID-BLACK / 纯色底） | 取色值与设计稿一致（ΔE 阈值，避免"看着差不多"） |
| IMG-VIS-03 | 视觉回归基线 | 固定图 + 固定视口 | 基线首次生成需人审；后续 diff 有遮罩规则（时间/随机内容） |

## API 事实与待核实项

已核对（来自 MasterGo 开发者平台文档，插件 API 侧）：

- 图片填充：遍历 `node.fills`，判断 `fill.type === "IMAGE"`，取 `fill.imageRef`
- 取图字节：`mg.getImageByHref(fill.imageRef)` → `imageHandle.getBytesAsync()` → `Uint8Array`
- 导出 PNG：`mg.exportPng({ ids, filterIds, scale })` → base64 data URL（文档标注为**私有化**能力）
- 导出 SVG：`mg.exportSvgByLayerIds(layerIds)` → SVG 字符串
- 节点查询：`mg.getNodeById(id)` / `mg.getNodeByPosition({x,y})`；节点含 `id` / `type`(FRAME/TEXT/VECTOR) / `bounds{x,y,width,height}`

**待核实（写用例前必须由研发或本 skill 使用者补上，禁止照抄猜测值）**：

- [ ] `imageFill` 的填充模式字段名与枚举值（FILL / FIT / STRETCH / TILE 的实际拼写）
- [ ] mask 图层的判定方式（是否有 `isMask` 字段，或靠父子关系推断）
- [ ] 混合模式字段（`blendMode`）是否在插件 API 暴露
- [ ] OpenAPI（服务端）侧的图片导出端点、鉴权方式、返回的是直链还是 base64
- [ ] 导出图片的存储位置与有效期（决定用例里引用的是短期签名 URL 还是长期直链）

未核实项一律在用例「前置」段写 `TODO：向 {谁} 确认 {什么}`，不得用"通常/一般应该是"填充。
